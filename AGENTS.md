# AGENTS.md

Aayatun: Flask + Jinja Quran web app. No build step, no bundler, no linter/formatter config, no automated tests, no CI. Frontend is server-rendered templates plus CDN jQuery/Fomantic and `static/`.

## Run & verify

- Run from the repo root; all data paths are relative (`db/…`, `db2/…`, `db3`).
- `flask --app app.py run --debug` (or `python3 -m flask --app app.py run`; see `run_command.md`). `app.py` has no `__main__`, so `python3 app.py` silently does nothing.
- Dependencies: `pip install -r requirements.txt`. Docs target Python 3.10; the local `venv/` is an ignored, empty Python 3.13 skeleton (pip only). Use a fresh 3.10 venv or a Python that already has the deps (`python3` here does).
- `db2/quran_metadata.db` is Git LFS (~311 MB). Without `git lfs pull` verse pages fail.
- No test suite. Smoke-check a route with the real stack (allow a few seconds for outbound calls):
  `python3 -c "import app; print(app.app.test_client().get('/2/255').status_code)"`

## Data layout (directory names are misleading)

- `db/` — live SQLite DBs and JSON/text indexes (`quran.db`, translation/tafsir DBs, `ai_context.db`, `page_overviews.db`, `quran_stat.json`, `quran_index.txt`, `ruku_index.txt`, `sarf.json`).
- `db/qcf_verses.json` — **tracked** seed of all 6,236 verses as `{"verses": [[surah, verse, mushaf_page, code_v2], …]}`, generated once from quran.com's `by_page` endpoints with the page column corrected to the **V2** (`v2_page`) Madani page used by the QPC2 fonts. It is the source of truth for QCF text and mushaf-page membership; `_qcf_load_cache` seeds the in-process dict from it (the sqlite cache is only a fallback). Page membership follows V2, not the per-verse `page_number`/V1 page (5:77 says 121 but belongs to V2 page 120). `qcf_page_index` and `library.get_mushaf_page(page)` derive from it. The 56 V1/V2 mismatches were fixed when the layout mode was added.
- `db/mushaf_lines.json` — **tracked** line layout for the optional mushaf view: `{"pages": {"604": [["h", 112], ["b"], ["x", [[112, 1, "glyphs", "plain text"], …]], …]}}` for all 604 V2 pages (1.9 MB). Generated from [zonetecde/mushaf-layout](https://github.com/zonetecde/mushaf-layout) `v2/mushaf/QPC2/page-XXX.json`; the glyphs are the same QPC V2 set as `code_v2`, so `/font/v4/<page>.woff2` renders them, and the fourth element is that fragment's plain Uthmani text (upstream `words[].word`, grouped by verse) for the normal-font view. `library.get_mushaf_lines(page)` lazy-loads it once; keep it in sync with `qcf_verses.json` page membership if either is regenerated. Upstream puts a surah's banner as the **last** line of the previous page when the surah starts at the top of a page (18 cases, e.g. ‘Abasa on 584/585); `_mushaf_fix_banners()` moves it above the next page's basmala on load, so no page ends with a dangling banner and the JSON can be regenerated as-is.
- The `.txt` indexes (`quran_index.txt`, `ruku_index.txt`, `pos_tags_dict.txt`) are Python literals read with `eval`, not JSON; keep them valid Python when regenerating.
- `ai_context.db.verse_analysis.verse` is **0-based** (0 = ayah 1), unlike every other table; `library.RootDefAdder` applies the `verse - 1` shift.
- `db/page_overviews.db` — **tracked** SQLite table `page_overviews(page, context, summary, model, generated_at)`, one row per printed Madani page. `context` explains why the passage sits at that point in the surah's flow, `summary` says what the page discusses. Generated offline by `/mnt/d/PROJECTS/aayatun_ai_content/generate_page_overviews.py` (Gemini/OpenAI, batched and resumable); `library.get_page_overview(page)` reads it with `lru_cache` and returns `None` for missing rows, so partial generation only hides the accordion. The generator must run from the app root (all data paths are relative) and never stores the API key.
- `db2/quran_metadata.db` — per-verse pickled dicts used by every verse page (`library.get_verse_pickle`). Git LFS.
- `db3/` — committed prebuilt Whoosh index powering `/search`. `searchtool.create_index()` needs `pd_backup.json`, which is not in the repo; don't try to rebuild the index here.
- `db/fonts/`, `db/qcf_cache.db`, `db/tajweed_cache.db` — gitignored runtime caches, safe to delete; they refetch on demand.
- The non-pickle code path is legacy: `getSurahInfo`, `get_morph`, `get_word_for_word_meaning` read `db/corpus.db`, `db/words.db`, `db/all_word_def.json`, none of which exist. Verse routes use `p_getSurahInfo()`.
- SQL is assembled with f-strings; route params are ints, but use bound parameters for any new string input.

## Architecture

- `app.py` holds all routes (flat, no blueprints). `/<surah>/<verse>` renders `versedetails.html` from `library.get_verse_core` (not `p_getSurahInfo`); `/search` is POST-only (form field `query_str`) and queries Whoosh. `/page/<n>` (1–604, prev/next wrap) renders one Madani mushaf page as a row-per-verse table grouped by surah (`templates/mushaf_page.html` + `library.get_mushaf_page`), with QCF text from the local seed. A third toggle, **Mushaf layout**, hides the table and the translation toggle and shows `library.get_mushaf_lines(page)` as printed lines (surah banner, Amiri basmala, glyph lines split into clickable verse segments that open the details modal); it is persisted in `localStorage['aayatun_mushaf_layout_v1']` and off by default. The tajweed button stays in this mode: off shows the same line breaks in plain Uthmani text (Scheherazade) instead of the QCF glyphs, re-fitting the line size on each toggle. That plain text ends each verse's Arabic-Indic number in parentheses (`(٢٥٥)`), done in `get_mushaf_lines`, not stored in the JSON. Table toggles default to plain text with translations shown, and both choices persist (`ayahTajweedOn` for the QCF font, `aayatun_mushaf_translation_v1` for translation). Controls are icon-only (`title` + `aria-label` + `aria-pressed`, Material `translate` SVG for translations) because the labels crowded narrow screens; the shared verse modal (`partials/_verse_modal.html`, also used by `/search`) is reused here. The verse page's main control row (next to share/play) carries an icon-only **Mushaf** button that opens `/page/<qcf_page>?v=<surah>:<verse>`; it removes itself when `window.self !== window.top` so it cannot navigate the parent out of an open modal, and it hides while the More menu is open. On arrival the page centres that verse and paints a 4 s highlight (`.mushaf-row-jump` in table mode, `.mushaf-seg-jump` across every segment in layout mode). On the index page, choosing **Jump to → page** disables the surah picker and the whole-surah buttons (`#whole-surah-row.is-disabled`), since neither uses a surah. The layout view's credit line names zonetecde/mushaf-layout (ISC) and the King Fahd Complex glyphs. Above the mushaf (both table and layout) sits a collapsed **Page Overview 🤖** accordion with the generated `context`/`summary` paragraphs and the shared AI warning banner (`partials/_ai_notice.html`, also used by the verse page's AI Overview). It reuses the verse accordion's 90% text size and is borderless (base.html injects inline `.accordion` borders in dark mode, so `static/css/style.css` overrides the overview with `!important`). Swiping left/right anywhere outside the controls moves to the next/previous page (left = next, matching the verse carousel); `ArrowLeft`/`ArrowRight` turn the page the way the on-screen header arrows read (left = previous, right = next), ignoring modifiers, typing targets and an open modal. Swipe uses the same pointer-drag model as `verse-nav.js` (axis detection, pointer capture, `preventDefault`, follow-the-finger, 25 %/velocity commit) but tracks the finger 1:1 (no half-speed factor, only the last 15 % damped) and writes the transform once per animation frame, with `will-change: transform` applied only while `mushaf-swiping`; the commit slide is 110 ms and the rejected-swipe ease-back 120 ms. The route sets `Cache-Control: private, max-age=300` and the script prefetches the two neighbour pages (plus their QCF fonts when tajweed is on) 900 ms after load, so a turn is a cache hit. The listener starts on `document` but ignores links/buttons, the verse modal/dimmer and accordion headers, so vertical drags still scroll and taps still open verses. `body.mushaf-page-body` sets `touch-action: pan-y pinch-zoom` and `overscroll-behavior-x: none`, and a short slide/fade precedes navigation unless `prefers-reduced-motion`.
- Verse pages ship only the current verse plus empty accordions. `GET /api/v1/verse/<s>/<v>` is the per-verse core payload (token-protected), `GET /api/v1/verse/<s>/<v>/<section>` renders one accordion section on demand, and `GET /api/v1/surah/<n>` returns the whole surah as compact `[[ayah, translation, page, codev2], …]` (no token, gzip, `no-store` so only the JS memory cache holds it). `library.get_surah_core` is `lru_cache(maxsize=4)` and reads only local DBs (`peek_qcf_ayah` never hits the network; the seed makes it always present).
- `static/js/verse-nav.js` keeps surah payloads in a memory-only LRU (3 entries) and drives the swipe carousel: two 3-pane tracks (ayah + translation), pointer drag with a 25 %/velocity commit, then `applyVerse()` + instant re-centre. No sessionStorage/IndexedDB/service-worker caching of the payload. It preloads the next/prev 3 page fonts.
- Offline verses: `verse-nav.js` writes every verse actually shown (max 60, LRU by timestamp) to `localStorage['aayatun_verse_offline_v1']` (Arabic, translation, QCF text/page, prev/next). `dataFor`/`loadVerse` fall back to it when the API is unreachable, and `static/offline.html` renders the saved verse when an uncached verse navigation fails offline. Do not grow this into a surah-payload cache.
- `templates/base.html` is the shared shell. `templates/comprehensive.html` extends it and is the layout for surah-wide pages (`translation`, `tafsir/*`, `mushaf`). `/mushaf/<surah>` (arabic fulltext) turns DataTables pagination off (`paging:false, stateSave:false`) so the whole surah scrolls like a mushaf; translation/tafsir keep pagination.
- Sharing: `static/js/share.js` (loaded by `base.html`) is the only implementation. `templates/partials/_share_macros.html` renders the icon button on `/page`, `/mushaf`, `/translation`, `/tafsir/en` and `/tafsir/bn`; the verse page's own `#share-btn` calls `AayatunShare.shareVerse` with `state.ayah` (the plain Uthmani text, kept separately from the QCF codepoints the h1 may hold). Text formats: verse = surah `S:V`, blank line, translation, `Read on Aayatun: URL`, `#aayatun`; surah = `Surah Name (N) — <view label> on Aayatun.` + URL + tag; page = `Madani mushaf page N — range` + `Read on Aayatun: URL` + tag. The URL lives inside the text (no separate `url` field) so it cannot be dropped or duplicated. Order: `navigator.share` (with the card when one exists), then clipboard + checkmark, then `window.prompt`. There is no download fallback: without file sharing the text is shared/copied.
- Share cards: only three surfaces get a PNG, and it is **drawn on a canvas**, never a screenshot (html2canvas was removed). `/<surah>/<verse>` → title + plain Arabic + translation; `/mushaf/<surah>` (arabic) → title + the surah's first verse; `/page/<n>` → title + the page's first verse. `/translation/*` and `/tafsir/*` are text-only. The title is Merriweather (`#4183C4`, `#9CC4FF` in dark) and reads `Al-Baqarah 2:255`, `Al-Baqarah (2)` or `Madani mushaf page 42` (the page card adds the range as a muted second line). Arabic is always `state.ayah` or the first `.mushaf-plain` in the DOM (both exist with tajweed on, and in the line layout), never `code_v2`, so the card is never coloured. The card is 420 CSS px wide at 2×, 20 px padding, word-wrapped by hand (`measureText`, `ctx.direction='rtl'` for the Arabic — bidi orders a pure-Arabic run correctly either way), grows with the verse, and keeps a 220 px minimum body so one-word verses do not become a strip. Band: `aayatun.com` + the full URL, shrunk to fit. `document.fonts.load()` warms Merriweather/Scheherazade/Open Sans at load, because with tajweed persisted ON the plain Arabic is never painted and Scheherazade might not otherwise be fetched. Drawing is synchronous (`toDataURL` → `atob` → `File`), so the whole thing stays inside the tap and Safari keeps its user activation; there is no warm-up cache, no scroll/resize listener and no `registerVerse`.
- `base.html` owns the default OG/Twitter meta (`og:site_name/type/title/description/url/image`, `twitter:card=summary`). The reading templates override `og_title`/`og_description`; the verse page also sets `og_type=article` and `meta_description`. `twitter:*` reuses `self.og_*()`, so override those blocks rather than writing raw tags.
- The index's **Surprise me!** button uses `surpriseTarget()`: 50% opens a random `/page/<1..604>`, otherwise the server-picked random ruku verse (`rand_surah`, unchanged). The branch is chosen in the browser with `Math.random()`, so the page response stays cacheable.
- `prayer-time.html` at the repo root is standalone (no Jinja, no base) and served verbatim at `/prayer-time` via `send_from_directory('.', …)`, so it must stay at the root. Its "See details" iframe loads `https://www.aayatun.com/<surah>/<verse>` unless the page is already on `aayatun.com`.
- Per-request network: alquran.cloud (tajweed markup) and quran.com (QCF `code_v2` + per-page COLRv1 fonts). Calls use short timeouts, sqlite caches, background warmers, and a plain-text fallback, so pages must still work when those APIs are down.
- `/font/v4/<page>.woff2` serves page fonts (1–604) with immutable caching and downloads them into `db/fonts/` on first use.

## Frontend gotchas

- Verse-page tajweed: the head script adds `html.tajweed-pending` (hides the server-rendered plain `h1`), and the parse-time script after the controls applies the colored rendering then calls `reveal()`. Keep that init parse-time; moving it back into `DOMContentLoaded` brings back the plain→tajweed flash. `VerseTajweed.renderInto(el, data)` paints any carousel pane (per-page `@font-palette-values`, fonts preloaded with `preloadPage`); the carousel keeps the only `id="ayah"` on the current pane, and neighbour panes are `div.ayah-text` (one `h1` per page).
- The navigation loading bar in `base.html` keeps `showLoading`/`hideLoading` outside jQuery/`DOMContentLoaded` and passes state across pages via `sessionStorage['aayatun_loading']` + `html.is-loading`; iOS Chrome needs this path.
- `static/service-worker.js` precaches the app shell and is registered only from `index.html`; bump `CACHE_NAME` when changing precached assets or caching logic. Every `respondWith` path must resolve to a `Response`: a failed fetch with nothing cached used to resolve `undefined` and throw "Failed to convert value to 'Response'", so the SWR/cache-first paths fall back to a 504 `networkError()` and navigations to `offline.html` then an inline 503 page.
- Mushaf layout view (`templates/mushaf_page.html`): its JS runs from the base page's `DOMContentLoaded` block, so `QcfFont` is already defined. It keeps the view `visibility: hidden` until the active face is painted (QCF if tajweed is on, plain Scheherazade otherwise) and the lines are fitted (measure at 100 px, scale the widest line to the column, re-fit on resize and on every tajweed toggle). Each segment holds both a `.mushaf-plain` and a `.mushaf-qcf` span, and only the visible one is measured, so the hidden face cannot stretch a line. Pages 1–2 additionally cap that size at `100 × avail ÷ 1640` because their printed lines are much shorter than a normal page's, which otherwise made their text ~20 % larger than the rest of the mushaf. Only lines flagged `endblock` (last line of a surah or of the page) may stay short; every other line is justified, which is why mid-verse line breaks must not be right-aligned. A verse split across lines shares one `data-surah`/`data-verse`, and the hover/focus handler toggles `.mushaf-seg-active` on every segment of it; the highlight is transient (cleared on leave/click, never stored). Because the glyph line box is tall (line-height 1.75), the highlight is a centred gradient band (`background-size: 100% 55%`) rather than a full-height background, so it does not bleed into the neighbouring lines. The 100 px measuring pass needs `.mushaf-layout { overflow: hidden }` or it flashes a horizontal scrollbar.
- The shared verse modal (`partials/_verse_modal.html`) reveals on the iframe's `DOMContentLoaded` (polled, 40 ms) instead of `load`, and the verse page's two `<audio>` tags use `preload="none"`, so opening a modal downloads no MP3s. Don't move back to `load` or `preload="auto"` without measuring: it added ~600 ms and two external requests per open. Hiding the modal (close icon, ESC, or `.modal('hide')`) pauses and rewinds every `<audio>` inside the iframe via the modal's `onHide`; the iframe keeps playing otherwise.
- **Recently Read** on the index is fed by `static/js/recent.js`, which records the three reading views through their server-rendered `<meta name="aayatun-read" content="type|key|label">` (`verse` = `/<s>/<v>`, `page` = `/page/<n>`, `mushaf` = `/mushaf/<surah>`). Entries live in `localStorage['aayatun_recent_reads_v1']` (max 5, newest first); revisiting a URL moves it to the front, and a run of the same kind collapses to its newest entry, so 42 → 43 → 44 leaves only "Page 44". Pages without the meta (home, search, translation, tafsir, prayer-time) never record, and the verse page skips recording inside the shared modal iframe (`window.self !== window.top`). The index renders the chips with `createElement`/`textContent` and its × clears the key.
- Frontend dependencies are CDN-only (jsdelivr jQuery/Fomantic, Google Fonts); there is no npm or build output.
- `prayer-time.html` keeps an offline copy of Aladhan calendar months in `localStorage['prayer-times-offline-v1']` (current + next month, keyed by place + `method`/`school`), so the times survive with no connection. Change the `-v1` suffix if the stored shape changes; old keys are ignored.
- PWA scope is fixed at install time: the manifest uses `id`/`scope`/`start_url` `/`, so the app must be installed from `https://www.aayatun.com` (the apex 301s there). An install made from the apex stays in the in-app browser and has to be removed and re-added.
- The iOS install UI is homepage-only (`templates/index.html`). Chromium's `beforeinstallprompt` still drives the Android/desktop banner and real prompt, but iOS never fires it, so the same `#install-banner` switches to `Install Aayatun` / "Tap Share, then Add to Home Screen" and `#install-btn` becomes `How?`, opening `#ios-install-modal`. Show it only for iOS/iPadOS (`MacIntel` + `maxTouchPoints > 1`), never in standalone (`display-mode: standalone|fullscreen` or `navigator.standalone`) and never in an in-app browser (`FBAN|FBAV|Instagram|WhatsApp|…`). Closing it stores `localStorage['aayatun_ios_install_dismissed_v1']`; `appinstalled` hides it. iOS cannot install programmatically — do not add a fake prompt. `static/images/apple-touch-icon.png` (180×180) is generated from `icon-512.png`.

## Repo

- Current branch `deploy` tracks `origin/deploy`; `origin` also has `master`, `develop`, `release`. No CI workflows.
- Python files indent with tabs (`app.py`, `library.py`); match that to avoid mixed-indentation errors.
- Don't commit `db/fonts/` or `db/*cache*.db` (gitignored); keep Git LFS installed for `db2/quran_metadata.db`.
